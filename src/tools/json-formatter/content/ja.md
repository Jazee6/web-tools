steps:
  - 入力欄に JSON を貼り付けるか入力します。
  - インデントを選びます。スペース 2 つ、スペース 4 つ、タブ、または 1 行にまとめる「圧縮」から選べます。
  - 必要に応じて「キーをアルファベット順に並べ替える」をオンにすると、すべての階層のオブジェクトのキーが並べ替えられます。

faq:
  - q: JSON はサーバーにアップロードされますか？
    a: いいえ。整形はブラウザに組み込まれた JSON パーサーですべてブラウザ内で行われるため、データが端末の外に出ることはありません。ページを一度読み込めばオフラインでも使えます。
  - q: 整形と圧縮の違いは何ですか？
    a: 整形（プリティプリント）は改行とインデントを加えて、人が構造を読みやすくします。圧縮は省略できる空白をすべて取り除き、保存や転送に適した最小の JSON を作ります。どちらもデータの中身はまったく同じです。
  - q: キーを並べ替えるとデータが変わりますか？
    a: 変わるのはオブジェクト内のキーの順序だけで、値、入れ子構造、配列の順序はそのままです。JSON のオブジェクトは本来順序を持たないため、並べ替えた結果も等価であり、2 つのドキュメントを比較しやすくなります。
  - q: JSON が無効と表示されるのはなぜですか？
    a: よくある原因は、末尾のカンマ、ダブルクォートではなくシングルクォートを使っている、キーをクォートで囲んでいない、コメントがある、NaN や undefined などの値がある、といったものです。これらは JavaScript では使えても JSON では使えません。エラーメッセージに、パーサーが受け付けなかった内容と位置が表示されます。
  - q: 非常に大きな数値は正確に保たれますか？
    a: 数値は標準の 64 ビット浮動小数点数として解析されるため、9,007,199,254,740,991 を超える整数は精度が失われることがあります。大きな ID を扱う場合は文字列として保存してください。

## この JSON フォーマッターでできること

ブラウザと同じ厳密な JSON パーサーで入力を解析するため、受け付けたものはすべて [RFC 8259](https://www.rfc-editor.org/rfc/rfc8259) に準拠した有効な JSON です。有効な入力は選んだインデントで出力し直し、無効な入力は勝手に「修正」せず、パーサーのエラーメッセージとともに拒否します。

## オプションと制限

- **インデント**：スペース 2 つ、スペース 4 つ、タブ、または 1 行への圧縮。
- **キーの並べ替え**：再帰的に、コードポイント順のアルファベット順で並べ替えます。配列の順序は変わりません。
- **サイズ**：端末のメモリだけが上限です。一般的なノート PC なら、数 MB の入力も 1 秒かからずに整形できます。
- **非対応**：コメントや末尾のカンマなど、JSON5 や JSONC の拡張構文。先に取り除いてください。

## プライバシー

処理はすべてお使いの端末上で行われます。このページは JSON をどこにも送信せず、保存もせず、Cookie も使いません。
