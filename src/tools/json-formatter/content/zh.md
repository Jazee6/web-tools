faq:
  - q: 我的 JSON 会被上传到服务器吗？
    a: 不会。格式化完全在你的浏览器里用内置的 JSON 解析器完成，数据不会离开你的设备。页面加载完成后，离线也能使用。
  - q: 格式化和压缩有什么区别？
    a: 格式化（美化）会加入换行和缩进，方便人阅读结构；压缩会去掉所有可省略的空白，得到体积最小的合法 JSON，便于存储和传输。两者的数据内容完全相同。
  - q: 按键名排序会改变我的数据吗？
    a: 只会改变对象内部键的顺序，值、嵌套结构和数组顺序都不变。JSON 对象本身就是无序的，所以排序后的结果是等价的，而且更便于比较两份文档。
  - q: 为什么提示我的 JSON 无效？
    a: 常见原因有：末尾多余的逗号、用了单引号而不是双引号、键名没加引号、包含注释，以及 NaN、undefined 这类值。它们在 JavaScript 中允许，但在 JSON 中不允许。错误信息会显示解析器拒绝的内容和位置。
  - q: 很大的数字能保持精确吗？
    a: 数字按标准 64 位浮点数解析，所以大于 9,007,199,254,740,991 的整数可能丢失精度。如果要处理很大的 ID，请把它们存成字符串。

## 这个 JSON 格式化工具做什么

它使用和浏览器相同的严格 JSON 解析器处理输入，凡是能通过的都是符合 [RFC 8259](https://www.rfc-editor.org/rfc/rfc8259) 的合法 JSON。合法的输入会按你选择的缩进重新输出；不合法的输入会直接报出解析器的错误信息，而不是被悄悄"修复"。

## 选项与限制

- **缩进**：2 个空格、4 个空格、制表符，或压缩为一行。
- **键名排序**：递归进行，按码位字母顺序排序；数组顺序永远不变。
- **大小**：只受设备内存限制。在普通笔记本电脑上，几 MB 的输入也能在一秒内完成。
- **不支持**：JSON5、JSONC 的扩展语法，例如注释和末尾逗号——请先删除它们。

## 隐私

所有处理都在你的设备上完成。页面不会把你的 JSON 发送到任何地方，不会保存它，也不使用 Cookie。
