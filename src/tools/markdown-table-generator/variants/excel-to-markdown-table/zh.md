faq:
  - q: 需要先把表格另存为 CSV 吗？
    a: 不需要。复制单元格时，电子表格会把它们以制表符分隔的文本放到剪贴板上：每行一行，单元格之间用制表符隔开。这正是这个预设读取的格式，所以复制粘贴就够了。
  - q: 为什么带千位分隔符的数字仍是一个单元格？
    a: 在制表符分隔的文本里，只有制表符会拆分单元格，所以 1,234.50 或 "red, green" 这样的列表都留在同一个单元格里。在以逗号作小数点的语言环境下，这正是从电子表格粘贴比导出 CSV 更可靠的主要原因。
  - q: 公式、颜色和合并单元格会被复制吗？
    a: 不会。剪贴板里是单元格显示的值，所以你得到的是公式的结果，而不是公式本身。粗体、颜色、边框等格式不属于文本；合并单元格会变成一个值，后面跟着空单元格。
  - q: 一个多行单元格把我的表格弄乱了，怎么解决？
    a: 电子表格复制含换行的单元格时会给它加上双引号，这个预设会把其中每个换行变成 <br>。如果换行仍然把一行拆开，说明你复制的程序没有给这个单元格加引号；请在表格中去掉换行后重新复制。

## 为什么复制单元格比导出更好用

Markdown 表格需要纯文本，而剪贴板里已经有了。电子表格应用复制一块区域时，用的是制表符分隔的值：每行占一行，单元格之间用制表符隔开。普通单元格的值里不会出现制表符，所以 1,234.50 这样的数字、地址和逗号分隔的列表都能完整保留——而当表格用逗号作小数点，或导出时用分号分隔时，CSV 导出就可能出错。

## 选项与限制

- **区域大小：** 最多 200,000 个字符的复制内容，足够容纳几千个短单元格。
- **复制的内容：** 只有显示出来的值，所以请在复制前在表格里设置好数字格式、日期和小数位。
- **空行：** 会被跳过；比其他行短的行会在末尾补上空单元格。
- **数字：** 如果表格大多是数字，把"对齐"选为"右对齐"，让它们在渲染后的表格里对齐。
- **不支持：** 公式、粗体或颜色等格式、合并单元格、图片和批注。

## 隐私

处理只在你的设备上完成。页面不会上传、保存你复制的单元格，也不使用 Cookie。
