  - q: '"URL 组成部分"和"完整 URL"有什么区别？'
    a: '"URL 组成部分"会转义除字母、数字和 - _ . ! ~ * '' ( ) 之外的所有字符，所以 / ? & = # 这样的字符也会被转义，适合处理 URL 里的单个值。"完整 URL"不会动构成 URL 结构的字符（: / ? # & = 等），只转义其余部分，所以整个地址仍然可用。'
  - q: 什么时候用"表单数据"？
    a: 处理 application/x-www-form-urlencoded 的值时使用，也就是 HTML 表单提交的格式，很多查询字符串也是这个格式。它把空格编码为 + 而不是 %20，同时转义 ! ' ( ) ~。解码时，+ 会变回空格。
  - q: 为什么解码时提示 % 序列有问题？
    a: 百分号后面必须正好跟两位十六进制数字，并且这些字节要构成有效的 UTF-8。纯文本里孤立的 %（例如"100%"）或被截断的序列（例如 %E4%B8）都会被拒绝。要表示字面的百分号，请写成 %25。
  - q: 用"完整 URL"解码时，%2F 会变回斜杠吗？
    a: 不会。"完整 URL"范围的解码会保持 %2F、%3F、%23 这类保留字符的转义不变，因为把它们变成真正的分隔符会改变 URL 的含义。要还原它们，请选"URL 组成部分"。

## 这个 URL 工具做什么

它按 [RFC 3986](https://www.rfc-editor.org/rfc/rfc3986) 定义的百分号编码处理文本：先转换为 UTF-8 字节，再把不允许出现的字节写成 %XX。"URL 组成部分"和"完整 URL"使用浏览器内置的 `encodeURIComponent` 和 `encodeURI`；"表单数据"遵循 [URL Standard](https://url.spec.whatwg.org/#application/x-www-form-urlencoded) 的规则。结果与你在自己的 JavaScript 里调用同样函数得到的一致。

## 选项与限制

- **模式**：把文本编码为百分号编码，或把它解码还原为文本。
- **范围**：URL 组成部分、完整 URL，或表单数据（空格转为 +）。范围对两种模式都生效。
- **仅限文本**：一次转换一个字符串，不会把 URL 拆分成各部分，也不会去请求它。
- **大小**：只受设备内存限制。

## 隐私

处理只在你的设备上完成。页面不会上传、保存你的文本，也不使用 Cookie。
