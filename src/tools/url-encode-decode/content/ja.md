faq:
  - q: テキストはサーバーにアップロードされますか？
    a: いいえ。エンコードもデコードもすべてブラウザ内で処理され、テキストがデバイスの外に出ることはありません。ページの読み込みが終われば、オフラインでも使えます。
  - q: 「URL の構成要素」と「URL 全体」の違いは何ですか？
    a: "「URL の構成要素」は、英数字と - _ . ! ~ * ' ( ) 以外のすべての文字をエスケープするため、/ ? & = # のような文字もエスケープされます。URL の中の 1 つの値に使います。「URL 全体」は、URL の構造を作る文字（: / ? # & = など）をそのまま残し、残りだけをエスケープするので、アドレス全体が使えるままです。"
  - q: 「フォームデータ」はどんなときに使いますか？
    a: application/x-www-form-urlencoded の値、つまり HTML フォームの送信形式や多くのクエリ文字列の形式で使います。スペースを %20 ではなく + にエンコードし、! ' ( ) ~ もエスケープします。デコード時は + がスペースに戻ります。
  - q: デコードで % の並びがエラーになるのはなぜですか？
    a: パーセント記号の後ろには 16 進数のちょうど 2 桁が続き、そのバイト列が有効な UTF-8 になっている必要があります。プレーンテキスト中の単独の %（「100%」など）や、途中で切れた並び（%E4%B8 など）は拒否されます。文字としての % は %25 と書いてください。
  - q: 「URL 全体」でデコードすると %2F はスラッシュに戻りますか？
    a: いいえ。「URL 全体」の範囲でのデコードでは、%2F、%3F、%23 などの予約文字のエスケープはそのまま残ります。本物の区切り文字にすると URL の意味が変わってしまうためです。戻したいときは「URL の構成要素」を選んでください。

## この URL ツールでできること

[RFC 3986](https://www.rfc-editor.org/rfc/rfc3986) で定められたパーセントエンコーディングを行います。テキストを UTF-8 のバイト列に変換し、使えないバイトを %XX で書き出します。「URL の構成要素」と「URL 全体」はブラウザ組み込みの `encodeURIComponent` と `encodeURI` を使い、「フォームデータ」は [URL Standard](https://url.spec.whatwg.org/#application/x-www-form-urlencoded) の規則に従います。結果は、同じ関数をご自身の JavaScript で呼び出した場合と一致します。

## オプションと制限

- **モード**：テキストをパーセントエンコードする、またはテキストに戻す。
- **範囲**：URL の構成要素、URL 全体、フォームデータ（スペースを +）。どちらのモードでも有効です。
- **テキストのみ**：1 つの文字列を変換します。URL を部品に分解したり、取得したりはしません。
- **サイズ**：デバイスのメモリだけが上限です。

## プライバシー

処理はお使いのデバイス上でのみ行われます。ページはテキストをアップロードも保存もせず、Cookie も使いません。
