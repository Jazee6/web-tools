faq:
  - q: トークンはサーバーにアップロードされますか？
    a: いいえ。トークンはすべてブラウザ内でデコードされ、デバイスの外に出ることはありません。ページの読み込みが終われば、オフラインでも使えます。ただし、本番システムで有効なトークンを、信頼できないサイトに貼り付けるのは避けてください。
  - q: このツールは署名を検証しますか？
    a: いいえ。3 つの部分をデコードするだけで、署名はトークンに書かれたままの形で表示されます。任意のクレームを持つトークンは誰でも作れるため、トークンを信頼する前に、発行元の鍵を使ってご自身のコードで署名を検証してください。
  - q: exp、nbf、iat とは何ですか？
    a: RFC 7519 に登録されている時刻クレームで、1970-01-01 UTC からの秒数で書かれます。exp はトークンの有効期限、nbf（not before）は有効になる時刻、iat（issued at）は作成された時刻です。表ではそれぞれを読みやすい UTC の日時に変換しますが、トークンが今期限切れかどうかは判定しません。
  - q: 5 つの部分からなるトークンでエラーになるのはなぜですか？
    a: 5 つの部分からなるトークンは暗号化された JWT（JWE）です。ペイロードが暗号化されているため、復号鍵がなければ読み取れません。署名付き JWT（JWS）は 3 つの部分からなります。
  - q: 署名が空のトークンもデコードできますか？
    a: はい。署名なしのトークン（"alg":"none"）は、末尾がドットで署名が空になります。通常どおりデコードできますが、クレームは何も保護されていないため、アクセス制御には決して信用しないでください。

## この JWT ツールでできること

JSON Web Token（[RFC 7519](https://www.rfc-editor.org/rfc/rfc7519)）は、base64url でエンコードされた 3 つの部分をドットでつないだものです。署名アルゴリズムを含むヘッダー、クレームを含むペイロード、そして署名からなります。デコーダーはトークンを分割し、ヘッダーとペイロードを base64url から UTF-8 にデコードして、インデント付きの JSON で表示します。クレームのうち `iat`、`nbf`、`exp` は数値の日時なので、UTC の日時としても一覧にします。

## オプションと制限

- **デコードのみ**：署名のチェックも、鍵の取得も、トークンと現在時刻の比較も行いません。
- **署名付きトークン**：署名が空の署名なしトークンを含め、3 つの部分からなるトークンをデコードできます。5 つの部分からなる暗号化トークン（JWE）は受け付けません。
- **厳密な形式**：ヘッダーとペイロードは JSON オブジェクトである必要があります。標準 Base64 の文字（+、/、=）を base64url の代わりに使うことはできません。
- **大きな数値**：クレームの値は JavaScript の数値として表示されるため、9,007,199,254,740,991 を超える整数は精度が失われることがあります。
- **サイズ**：デバイスのメモリだけが上限です。

## プライバシー

処理はお使いのデバイス上でのみ行われます。ページはトークンをアップロードも保存もせず、Cookie も使いません。
