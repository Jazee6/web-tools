faq:
  - q: Markdown 内の HTML はそのまま残りますか？
    a: はい。<details>、<kbd>、幅を指定した <img> などの生の HTML は、CommonMark の仕様どおり変更せずに出力されます。プレビューはスクリプトを許可しないサンドボックスのフレームで表示されるため、Markdown 内の <script> がこのページで実行されることはありません。ただし出力には含まれるので、HTML を公開した先で実行される可能性があります。信頼できる Markdown だけを変換してください。
  - q: 見出し ID はどのように作られますか？
    a: GitHub がアンカーに使うルールに従います。Markdown や HTML のタグを除いた見出しのテキストを小文字にし、句読点、記号、絵文字を取り除き（ハイフンと _ などの連結用の句読点は残します）、スペースをハイフンに置き換えます。たとえば "What's new in v2.0?" は id="whats-new-in-v20" になります。どの文字体系の文字も残るため、日本語やキリル文字の見出しはそのままです。同じ見出しが複数あると -1、-2 などが付き、絵文字だけの見出しのように何も残らない場合は ID を付けません。「見出し ID を付ける」をオフにすると ID は付きません。
  - q: HTML フラグメントと完全な HTML ドキュメントの違いは何ですか？
    a: フラグメントは変換した内容だけで、独自の <head> とスタイルを持つページ、CMS、テンプレートにそのまま貼り付けられます。完全な HTML ドキュメントは <!doctype html>、<head>（タイトルは文字のある最初の見出し 1、なければ "Document"）、小さな既定のスタイルシートを加えたもので、.html ファイルとして保存してブラウザで開けます。
  - q: シンタックスハイライトはどのように動作しますか？
    a: 開始フェンスの後に言語名を書いたコードブロック（例：```python）は、Shiki ハイライターで色付けされます。色はすべてインラインスタイルで書かれるため、別のスタイルシートは不要です。ただし、インラインスタイルを削除するエディターでは色も消えます。言語名がないコードや、Shiki が認識しない言語のコードはそのままです。シンタックスハイライトは既定でオフで、その場合は言語名のあるコードブロックに独自のハイライターで使える <pre><code class="language-…"> を、それ以外には通常の <pre><code> を出力します。
  - q: Markdown は保存されますか？
    a: ブラウザがサイトのデータ保存を許可している場合は保存されます。入力をやめて少し経つと「Markdown」欄の内容がこのデバイスに保存され、次に開いたときに復元されます。アップロードされることはありません。サイトのローカルデータを消去すると削除されます。

## Markdown HTML 変換の仕組み

[marked](https://marked.js.org/) で Markdown を解析し、[CommonMark](https://commonmark.org/) に加えて GitHub Flavored Markdown の表、タスクリスト、取り消し線、URL の自動リンクに対応します。出力は marked が生成する HTML と同じで、GitHub 形式の見出し ID を付け、オンにした場合は [Shiki](https://shiki.style/) でコードをハイライトします。変換はページ本体ではなく、ブラウザのバックグラウンドスレッドで行われます。

## オプションと制限

- **Markdown：** 最大 200,000 文字。
- **生の HTML：** 変更もサニタイズもせずに残します。プレビューでスクリプトは実行されませんが、出力には含まれます。
- **見出し ID：** 既定でオン。GitHub のアンカーのルールで作り、同じ見出しには -1、-2 を付け、処理後に何も残らない見出しには付けません。
- **完全な HTML ドキュメント：** 既定でオフ。doctype、最初の見出し 1 から取ったタイトル、既定のスタイルシートを加えます。
- **シンタックスハイライト：** 既定でオフ。GitHub Light、GitHub Dark、One Dark Pro、Vitesse Light から選べ、色はインラインスタイルで書かれます。テーマと各言語の文法ファイルは初めて必要になったときにダウンロードされるため、少し時間がかかることがあります。オフラインなどでダウンロードに失敗した場合、コードブロックはハイライトされません。
- **コピー：** どちらのボタンもブラウザのクリップボードを使い、ブラウザによっては許可が必要です。「リッチテキストをコピー」には、書式付き HTML をコピーできるブラウザも必要です。
- **非対応：** 脚注、数式、Mermaid などの図は、プレーンテキストやコードブロックのまま残ります。YAML のフロントマターは取り除かれず、ほかの Markdown と同じように変換されます。

## プライバシー

処理はお使いのデバイス上でのみ行われます。ページは Markdown をアップロードもサーバーに保存もせず、Cookie も使いません。
