faq:
  - q: なぜブラウザではなくサーバーで確認するのですか？
    a: ブラウザはセキュリティ上の理由から、ほかのサイトのレスポンスヘッダーの大半をスクリプトから読めないようにしています。そのためサーバーがリクエストを送り、ステータス、ヘッダー、リダイレクト先だけを返します。ページ本文は返しません。
  - q: どのリクエストメソッドを使いますか？
    a: 常に HEAD リクエストを送り、ページをダウンロードせずにヘッダーだけを取得します。HEAD と GET で応答が異なるサーバー（405 Method Not Allowed を返すなど）もあり、その場合はサーバーの応答をそのまま表示します。
  - q: localhost や社内ネットワークのアドレスも確認できますか？
    a: できません。プライベートネットワークを守るため、localhost、10.x.x.x、192.168.x.x、リンクローカルなどの予約済みアドレスは拒否され、80 と 443 以外のポートも使えません。
  - q: リダイレクトのステータスコードにはどんな意味がありますか？
    a: 301 と 308 は恒久的なリダイレクトで、検索エンジンはリダイレクト先に評価を引き継ぎます。302、303、307 は一時的なリダイレクトです。307 と 308 ではリクエストメソッドも変わりません。
  - q: 確認できる回数に制限はありますか？
    a: はい。無料でサービスを提供し、同じサイトへの繰り返しのリクエストを避けるため、訪問者ごと・対象サイトごとに回数を制限しています。上限に達したら 1 分ほど待ってから再度お試しください。

## このヘッダーチェッカーでわかること

入力したアドレスに HEAD リクエストを送り、サーバーの応答を表示します。HTTP ステータスコード、サーバーが返したレスポンスヘッダー（名前は小文字）、そしてリダイレクトをたどる場合は各ホップのステータスコードです。`cache-control` などのキャッシュヘッダー、`strict-transport-security` や `content-security-policy` などのセキュリティヘッダーの確認、古い URL が意図した場所へリダイレクトされているかの確認に役立ちます。

## オプションと制限

- **リダイレクト：**最大 5 ホップまでたどり、各ホップはリクエスト前に改めて検証します。
- **タイムアウト：**リダイレクトを含め、確認全体を 8 秒以内に終える必要があります。
- **アドレス：**標準ポート 80 と 443 の公開 `http://`・`https://` URL のみ。
- **回数制限：**訪問者ごとに 1 分あたり数回、対象サイトごとにも上限があります。
- **対象外：**ページ本文、ブラウザ内の Cookie、HTTP/2・HTTP/3 のプロトコル詳細。

## プライバシー

入力した URL はリクエストを送るためだけにサーバーへ送信され、保存されません。確認のリクエスト内容も記録しません。対象サイトから見ると、リクエストはあなたではなく当サーバー（WebToolsBot）から届きます。
